# AI Usage and Architectural Decisions

## Overview
During the development of the **Smart Parking License Plate Tracker (Track 1 - Lite)** project, AI tools were used to assist with Docker Compose orchestration, GitHub Actions CI/CD automation, GHCR bonus integration, and troubleshooting repository permissions.

## Sample Prompts Used
1. "Help me configure a `docker-compose.yml` file to run an Nginx web dashboard on port 8080 and an Apache storage server on port 8081 with a persistent Docker volume."
2. "How do I update my existing GitHub Actions workflow to build and push Docker images to GitHub Container Registry (GHCR) without breaking the current CI setup?"
3. "Design a clean HTML dashboard in Hebrew for a smart parking lot security guard that displays incoming vehicle images from the storage service."

## AI Errors / Inaccuracies Encountered & How We Resolved Them

### Error 1: Over-complicated Workflow Rewrite & Incorrect Image Naming
* **What the AI suggested:** When asked to add the GHCR bonus step, the AI initially generated a completely rewritten GitHub Actions workflow that changed the job names, downgraded `actions/checkout` from `v6` to `v4`, and used custom `docker build` commands with hardcoded image names (`smart-parking-web`) instead of using our existing `docker-compose.yml` build structure.
* **How we fixed it:** We rejected the full rewrite to avoid breaking our already working CI pipeline. Instead, we kept our original `docker compose config -q` and `docker compose build` steps intact and only appended the `docker/login-action@v3` and `docker tag` / `docker push` commands matching the actual image names generated by Docker Compose (`smart-parking-web-service` and `smart-parking-storage-service`).

### Error 2: Assuming Repository Owner Permissions for GHCR Settings
* **What the AI suggested:** The AI instructed us to go to `Settings -> Actions -> General -> Workflow permissions` in GitHub to manually enable "Read and write permissions" for `GITHUB_TOKEN`.
* **How we fixed it:** Because one team member was working as a Collaborator rather than the repository owner, the repository settings tab displayed *"You don't have access to repository options"*. We resolved this directly inside the `.yml` workflow file by explicitly declaring `permissions: contents: read` and `packages: write` at the job level, bypassing the need for manual UI settings.
